# CobbleMarket RP 充值（游戏内档位 + 个人收款码）

本文档写给**自己收款的服主**：玩家在游戏里选档位、扫你的收款码付款、点「我已支付」，
你在管理端核对账单后一键发放 RP。

如果你的服务器**已经有自己的充值网站**，请看另一份文档 [RP 外部签名码](/points-external) ——
那份讲的是"网站在线支付 → 自动拿到兑换码"。

## 一、先理解这套设计的出发点

国内小服主普遍用**个人收款码**（微信 / 支付宝）卖东西，而**个人收款码没有支付回调** ——
任何程序都无法自动得知"谁付了多少"。所以本功能的目标**不是"自动收款"，而是把对账成本压到最低**。

三条铁律，出自安全考虑，请先接受再往下看：

- 模组**不看钱、不碰钱、不做支付通道**：收款码是你的，钱直接进你自己的账户
- 模组**无法判断支付是否成功，也不假装能判断**：玩家点「我已支付」**只是一个声明，不是证据**
- **失败方向必须是安全的**：「没付却说付了」**不会发货**（你不确认就不发放）；
  只有「付了但你没看到」会漏发 —— 可以用待确认列表 + 订单号补回来。
  **宁可漏发，不能滥发。**

## 二、怎么开

1. 先确认**RP 总开关**是开的（`pointsEnabled`）
2. 打开**游戏内充值开关** `pointsShopEnabled`（默认关）
3. 配好你的**收款码**（见第四节）与**档位**（见第三节）
4. 在游戏内管理界面里配置，或直接改 `config/cobblemarket/cobblemarket.json` 的 `pointsShop` 段

> 管理员可以在游戏内打开 **RP 配置界面**完成这些（收款码、券图、货币单位、档位都能在里面配），
> 界面上也标了图片该放哪个目录。改 json 也可以，两者等价。

## 三、配置项（`pointsShop` 段）

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `false` | 是否开启游戏内充值（**需 RP 总开关同时开启**） |
| `payQrImage` | `""` | **全局**收款码文件名（放 `config/cobblemarket/qr/` 下，只认 PNG）。**留空 = 不开放「购买 RP」**（玩家仍可用兑换码充值） |
| `defaultIcon` | `""` | 档位「RP 券」的**全局默认**图（放 `config/cobblemarket/icons/` 下）。优先级：档位专用图 > 本项 > 模组内置券图 |
| `currencyLabel` | `""` | 档位金额的**货币单位**，纯展示用，你自己填 `元` / `USD` / `$`。**留空 = 只显示数字**。模组不做任何汇率换算 |
| `orderTimeoutMinutes` | `15` | 待支付订单超时（分钟，1~1440）：超时作废，玩家可重新下单 |
| `tiers` | `[]` | 档位列表（见下）。**空数组 = 不开放购买入口**；非法档位在读取时被丢弃并记日志 |

**每个档位**有四个字段：

| 字段 | 说明 |
|---|---|
| `name` | 档位名称（玩家看到的） |
| `priceCents` | 标价，**单位是「分」**（`500` = 5.00）。⚠ 用整数存，浮点在对账场景里是致命的 |
| `points` | 这一档给多少 RP |
| `qr` | 该档**专用**收款码文件名（可空）。见下面两种模式 |
| `icon` | 该档「RP 券」图文件名（可空，留空走全局默认/内置图） |

### 两种收款码模式（**对账方式不同，务必选对**）

| | 用**全局**收款码（档位 `qr` 留空） | 用**档位专用**收款码（`qr` 填了） |
|---|---|---|
| 实付金额 | **档位标价**（玩家自己输金额） | **档位标价**（金额写死在码里，扫了直接付、不会输错） |
| 适合 | 普通静态收款码 | 微信/支付宝的**「设置金额」码** |
| 对账靠什么 | 账单里的**金额 + 时间**，配合玩家报的订单号 | 同左 |

> 两种模式玩家看到的实付金额都是**档位标价本身**，模组不会额外加任何钱。

> ⚠ 用专用码时，**档位标价必须与码上金额一致**，否则玩家付的钱跟订单对不上。

## 四、收款码与券图放哪

| 类型 | 目录 | 要求 |
|---|---|---|
| 收款码 | `config/cobblemarket/qr/` | 只认 **PNG**，单张 ≤ **512KB**、≤ 2048×2048。服务端读取后**下发给客户端**绘制，所以专用服务器上的玩家也能看到 |
| 档位券图 | `config/cobblemarket/icons/` | 同上；不配就用模组内置券图 |

收 款 码在**下单时**会快照进订单 —— 中途换图不影响已创建的订单。

## 五、流程

### 玩家侧

1. 入口界面 →「RP 商城」→「购买 RP」→ 选档位
2. 弹窗显示**收款码 + 订单号 + 实付金额**，按提示扫码付款
3. 付完点「**我已支付**」→ 订单进入「待确认」
4. 「我的订单」里随时可查自己的全部订单（含已发放 / 已作废的历史）

> 「实付金额」与订单号是**动态绘制在收款码旁**的（不写进图片文件）——
> 这样玩家截图转给别人代付时，对方看不到这两个信息，无法冒领。

### 服主侧

1. 管理面板 →「**充值订单**」（有待确认订单时入口挂角标，在线管理员还会收到聊天提醒）
2. 打开自己的收款账单，用**实付金额**或**订单号**找到那一笔
3. 核对无误 → 一键发放（RP 自动进玩家余额 + 写审计日志 + 写订单流水）
4. 发现是假报 → 作废

### 状态机

```
[待支付] --玩家点「我已支付」--> [待确认] --服主确认--> [已发放]
    |                              |
    +-- 超时 / 玩家取消 --> [已作废]  +-- 服主作废 --> [已作废]
```

- **[待支付]**：超时（默认 15 分钟）或玩家取消即作废
- **[待确认]**：**不会超时** —— 玩家**已经付款了**，自动作废等于吞钱；列表会显示已等待多久
- **[已发放]**：发放是**幂等**的：重复点确认、崩溃后重开再点，都不会重复加余额

## 六、对账：两条匹配键（核心）

服主核对时**两个键都可用**，管理端列表把两个都显示出来：

| 匹配键 | 什么时候用 |
|---|---|
| **实付金额（就是档位标价）** | **国内个人收款码**：没有手续费，付 5.00 到账就是 5.00，对着账单按金额找 |
| **备注 / 订单号** | **PayPal / Stripe 等有手续费的渠道**：付 5.00 到账可能只有 4.75，**金额对不上**，必须让玩家备注订单号 |

> ⚠ 结论：**金额只是线索之一** —— 同一时间有两笔同档订单时，账单上就是两个一样的数字，分不出谁是谁，
> 以**订单号**为准。用有手续费的渠道时，务必让玩家看到「请备注：XXXXXX」的提示。

**订单号**：6 位、Crockford Base32（剔除易混的 I/L/O/U），**末位是校验位** ——
玩家抄错一位，你这边一眼就能看出"这号不存在"，而不是查半天。玩家可凭订单号申诉，
管理端支持按**玩家名或订单号**搜索。

## 七、常见问题

### 一次能下几单？

一个玩家最多同时有 **3 个未完结订单**（想改充别的档位时不必先取消）。

### 玩家超时之后才回来点「我已支付」怎么办？

超时后有 **30 分钟宽限期**仍然接受「我已支付」—— 玩家可能已经扫码了，只是回来点得慢。

### 有没有可能重复发放？

不会。发放是幂等的：只有「待确认」状态的订单能被发放，你重复点、界面重发、崩溃后重开列表再点，
都只会成功一次。

### 审计在哪？

- RP 的每一次变动（含这次发放）：`config/cobblemarket/points/` 下的 CSV
- 订单流水（创建 / 玩家声明已付 / 发放 / 作废）：同目录的另一份 CSV
- 交易账本（RP 在市场里流通的每一笔）：`config/cobblemarket/history/` 下的每日 CSV

### 已完结的订单会一直留着吗？

保留 **90 天**后清理 —— 这段时间足够你跟收款账单逐笔对账。
