# 权限节点（服主向）

市场的管理权限由**权限节点**决定 —— 谁管哪一块、发给谁，由服主说了算。

**市场不认 OP 等级**：`/op` 是原版命令、可以被任何 OP 传递给别人，所以认 OP 等于给整套权限体系开后门。本页是给服主的配置指南。

## 一、先配置你的服主身份

**这是第一件要做的事**：名单为空时，谁都没有管理权限（管理员面板进得去、但所有功能都是灰的，服务器配置也改不了）。

**服主 = `config/cobblemarket.json` 里 `serverOwners` 名单中的人**（只存 UUID，改名不影响，也不会被重名顶替）。

服主拥有全部管理权限，并且是唯一能编辑服务器配置、给他人分配权限的人。

**怎么把自己加进名单**（只能手编配置文件，没有命令入口）：

1. 打开 `config/cobblemarket.json`，找到 `serverOwners` 数组
2. 填入你的 **UUID**（⚠ 别填游戏名 —— 那不会生效）
3. 保存后重启，或在游戏内执行 `/market reload` 立即生效

**UUID 的两种拿法**：

| 方式 | 怎么拿 |
|---|---|
| 查对照表 | 服务器运行目录下的 `usercache.json`（「玩家名 → UUID」对照表）；单机即 `.minecraft/usercache.json`，开了版本隔离的看对应版本目录 |
| 游戏内获取 | 执行 `/data get entity @s UUID`，把打出来的整串直接粘进去 —— 形如 `[I; 1804442506, -1786753140, -1221778941, 685026979]`，这种写法也认 |

**写法示例** —— JSON 字符串数组，每项用**英文双引号**包住、多条之间用逗号分隔：

```json
"serverOwners": [ "6b8d9b8a-9580-4f8c-b72d-220328d4aea3" ]
```

两个服主：

```json
"serverOwners": [
  "6b8d9b8a-9580-4f8c-b72d-220328d4aea3",
  "0ac1558a-9580-4f8c-b72d-220328d4aea3"
]
```

> ⚠ 少一个引号，**整份配置都读不了**（不是只失效那一条）—— 写坏了模组会**保留原文件不动**（方便你对着找问题）、另存一份 `.broken` 留档，并在日志里说明原因，调过的费率参数不会丢

**确认配好了**：启动日志会打印「已加载 N 名服主」；游戏内 `/market owner list` 可查看名单（只读）

> ⚠ 名单为空 = **谁都没有管理权限**（安全默认）；服务器启动时会提示怎么配

## 二、十四个管理节点

| 节点 | 管什么 |
|---|---|
| 黑名单 | 把精灵/物品加入黑名单或移出（拉黑后不能上架）|
| 价格限制 | 给精灵/物品设价格上下限（超出范围不能上架）|
| 封禁 | 封禁/解封玩家、查看封禁名单 |
| 挂单管理 | 下架任意玩家的精灵/物品 |
| 交易历史 | 查看全服所有人的交易记录（谁买了什么、花了多少、什么时候）|
| 拍卖管理 | 强制取消任意玩家的拍卖 |
| 求购管理 | 强制取消任意玩家的求购单 |
| 金融管理 | 管理玩家卡片、禁止借款、调整玩家额度；查看全服借贷流水（撤销坏账仅服主）|
| 市场开关 | 紧急停市 / 恢复市场（影响全服）|
| 查余额 | 查看**任何人**的 RP 余额（查自己不需要节点）—— 只读，可放心给客服核对 |
| 兑换码 | 生成 / 列表 / 作废 / 清理兑换码 —— ⚠ **等于印钞**；列表也能复制完整码并自行兑换，整个节点就是发码权，别当成"只读列表" |
| 充值订单 | 核对收款、确认发放 / 作废充值订单 —— ⚠ **确认即加余额**；授予前先确认对方看得到收款账单 |
| RP 商城 | 上架 / 编辑 / 下架 RP 商城的商品 —— 决定玩家花 RP 能换到什么 |
| 玩家总览 | 查看全服每个玩家的市场与经济数据（余额、挂单数、额度、借款、存款与利息、图鉴数；含 RP 余额，可按 RP 排序）|

> ⚠ **「玩家总览」等于让对方看到全服所有人的余额与债务** —— 节点授予是全给、收不回来，授予前先确认对方值得信任

> ⚠ **市场开关有意独立成节点**：紧急停市是影响全服的核按钮，与「下架一个违规挂单」份量差一个数量级 —— 绑在一起等于「想找人帮忙看挂单，就得把停市权一起给他」。想合并的人同时勾两个即可

> ⚠ **撤销坏账不在任何节点里**：它是服主的干预手段，只认服主 —— 借出去的钱收不回来时，那是最后的兜底

> ⚠ **四个 RP 节点里有两个是发钞权**：「兑换码」生成码等于凭空造 RP（列表里还能复制完整码），「充值订单」确认订单等于加余额。授予前先想清楚对方是谁

> ⚠ **RP 这块不认 OP**：RP 商城上下架、兑换码生成、RP 配置读写都按上面的节点或服主名单判定；RP 配置读写**只限服主**（里面有外部签名码密钥）

**「give/take 权限下放」开关**（RP 配置界面，默认关）：打开后**玩家身份的 OP（命令等级 ≥ 2）**也能用 `/market points give|take` 发放 / 回收 RP。

- 用途：任务模组以**完成任务的玩家身份 + N 级权限**执行命令（FTB Quests 的「运行等级」），不是服主也不是控制台；不开这个开关，任务奖励永远发不出去
- 给服主的两步操作：① 打开开关 ② 任务奖励写 `/market points give @s N` 且**运行等级设 ≥ 2**
- ⚠ **打开 = 接受「任何玩家 OP 都能发 RP」**（`/op` 可被转授）；只把 RP 当充值货币、由你手动发放时保持关闭
- ⚠ 这个开关**只管 give/take 两条命令** —— 权限授予、撤销坏账等仍然只认服主

## 三、怎么给玩家分派节点

服主在游戏内操作：**入口界面 → 管理员面板 → 权限管理** —— 搜索玩家、勾选节点、保存即生效。

- **在线玩家不必重进游戏**，界面按钮立刻点亮
- 当事人会收到一条聊天提示（告诉他权限变了什么）；离线期间发生的变更，上线时补发
- 命令方式：`/market perm grant|revoke|list`（仅服主）

## 四、OP 在这套体系里是什么

**OP 与普通玩家几乎完全一样**：管理操作一律按权限节点判定，OP 不会因为等级获得任何权限。

唯一的区别：**没有任何权限节点的 OP 仍能看到管理面板按钮** —— 进去后所有功能都是置灰的（包括只限服主的「权限管理」「服务器配置」），悬停会提示该找服主把自己写进 `serverOwners`。这是有意保留的**教学入口**。

> ⚠ 另一个例外：**`/market reload` 仍对 OP 开放** —— 服主手编配置后靠它生效，单机开作弊的房主也能用

> ⚠ **RP 侧的例外（默认关闭）**：RP 配置里的「give/take 权限下放」开关打开后，**玩家身份的 OP（命令等级 ≥ 2）**也能用 `/market points give|take` 发放 / 回收 RP。这是给任务模组（FTB Quests 等）用的；开关默认关，且**只管这两条命令**。详见第二节

## 五、为什么市场不接 LuckPerms 这类权限插件

因为**「权限节点不可传递」是这套设计的根基**：接了外部权限源，「谁能发市场权限」就变成了「谁有 `luckperms.*`」，而那条链是可传递的 —— 等于把根基交出去。市场只认服主名单，而名单只能改服务器上的文件。
