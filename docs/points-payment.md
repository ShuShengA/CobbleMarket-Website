# 网站支付接入（框架与边界）

这一页讲**要不要做、要准备什么**，不讲具体平台怎么接。RP 的收款方式有两条路，本质区别只有一个：**谁来判断「钱到了」**。

## 一、两条路的本质区别

| | 人工确认（游戏内收款码） | 全自动（自己的网站） |
|---|---|---|
| 谁判断付款成功 | **服主**看收款账单 | **网站后端**接收支付回调 |
| 玩家拿到 RP 的时机 | 服主点「确认发放」后 | 回调验签通过后自动签发兑换码 |
| 对账依据 | 订单号 + 账单 | 回调流水 + 兑换记录 |
| 需要什么 | 一张个人收款码 | **公网可访问的后端** + **能回调的支付渠道** |

两条路可以并存：急着上线先用人工确认，网站搭好后再加全自动。

## 二、全自动的前提

1. **公网后端**：接收支付渠道的回调（异步通知）。没有公网地址，渠道找不到你
2. **支付渠道能回调**：不是所有收款方式都有异步通知；只有「设置金额」的静态收款码通常没有
3. **验签**：回调必须验证签名，否则任何人都能伪造一条「已支付」通知
4. **幂等**：同一条回调可能重复送达；同一个订单只能发一次码、只能加一次余额

> ⚠ **别把验签和幂等当成可选项**：这两条是安全底线，不是优化项。省掉任何一条，等于把「发 RP」的入口开给全互联网。

## 三、资质事实（国内）

- 国内个人通常拿不到支付渠道的**官方商户接口**（要营业执照，卡的是资质不是技术）
- 现实可选项：**发卡网**（手续费高、有跑路风险，自己评估）、**有资质的实体**（公司 / 个体户），或**继续用人工确认那套**
- ⚠ 本页不推荐具体平台、不提供绕开资质的办法 —— 支付合规是网站运营方自己的事

## 四、模组参与到哪里为止

**模组不参与支付。** 它不知道你用什么渠道收钱、也不关心。

模组要求的只有一件事：你的后端能算出**正确签名的兑换码**。网站付款成功后，后端按 [RP 外部签名码](/points-external) 的协议签一张码发给玩家，玩家在游戏内兑换 —— 全程不需要游戏服务器与网站直接通信。

- ✅ 模组负责：验签、兑换、记兑换记录
- ❌ 模组不负责：收款、支付状态、退款、售后

## 五、该不该做

- **只卖少量 RP、玩家不多**：先用游戏内收款码 + 人工确认，成本最低，对账也直接
- **有稳定流水、想自动化**：先把公网后端、回调验签、幂等这三件事做扎实，再考虑接渠道
- **没有营业执照**：别为了「全自动」去找绕开资质的办法 —— 人工确认那套本来就是为这个场景设计的
