# RP 系统（高级货币）

RP 是本模组的**高级货币**，与主货币并行流通：市场、拍卖场、求购单里都可以二选一标价。

RP **不可兑换、不可转让，也不参与金融** —— 喵喵银行的手续费与折扣只跟主货币有关。

> ⚠ **RP 从哪来，由服主决定**：它不绑定任何获取途径。当任务 / 活动奖励发、当充值货币卖、两者并用，甚至完全不开充值那套，都行。

## 一、先打开总开关

RP 相关开关在**服务器配置 → RP 配置**里（仅服主）。RP 总开关**默认开启**，关闭时玩家设置价格的界面不出现 RP 按钮，除 RP 商城外的任何地方都不能用 RP 交易。主 RP 商城另有**单独的开关**（默认关闭，不会出现一个空商城）；**自定义 NPC 商店不受这两个开关影响**。

| 配置项 | 默认 | 说明 |
|---|---|---|
| `pointsEnabled` | `true` | RP 总开关。关闭后玩家之间（以及玩家与市场）都不能用 RP 交易；服主仍可在 RP 商城上架，供已经持有 RP 的玩家购买。⚠ 升级时保留原值 |
| `pointsMainShopEnabled` | `false` | **主 RP 商城开关**：关闭时商城入口置灰、点击提示未开放。⚠ 旧配置没有这个键时跟随 `pointsEnabled`，升级不改变现有 RP 服的行为 |
| `pointsMarketEnabled` | `false` | **玩家间 RP 交易开关**：关闭时上架与市场界面里的 RP 货币按钮置灰，服务端也拒绝 RP 挂单。⚠ 关掉只禁玩家之间，充值、RP 商城与余额显示不受影响 |
| `rpAsQuestCurrency` | `false` | **give/take 权限下放**：打开后玩家身份的 OP（命令等级 ≥ 2）也能发放 / 回收 RP，用于任务奖励。详见第四节 |
| `pointsRewardsEnabled` | `false` | **奖励规则总开关**：打开后数据包里配的奖励规则才会生效。⚠ 如果你把 RP 当充值货币卖，打开它等于自动给玩家发钱 |

RP 的四种交易费率（精灵上架 / 物品上架 / 拍卖 / 求购）默认都是 **0**（免收），只能在 `config/cobblemarket.json` 里改，游戏内配置界面没有这几项。如果 RP 是真钱充值来的，建议保持 0 —— 扣它等于回收玩家花钱买的东西。

> ⚠ 玩家间 RP 交易是 RP「不可转让」设定在市场上唯一的后门：玩家 A 挂 RP 单、玩家 B 买下，本质就是把 RP 从 B 转到 A。只想让 RP 单向流入（充值 / 奖励）时，保持 `pointsMarketEnabled=false`。

## 二、RP 从哪来

RP 有四条发放路径，可以同时使用：

| 方式 | 谁生成 | 服务器存不存 | 能作废 / 列出 / 限次 / 绑定 |
|---|---|---|---|
| `/market points give` | 服主游戏内直接给 | —（直接到账） | — |
| 本地码 `/market points code create` | 服主游戏内生成 | **存表** | 全都能 |
| 外部签名码（自己的网站 / 发卡网） | 服主在**服务器之外** | **不存**，只记已用 serial | 都不能 |
| 游戏内充值 / 数据包奖励 | 玩家付款 / 玩家做游戏内行为 | 订单与奖励进度另存 | 充值订单可作废；奖励进度可重置 |

### 2.1 直接发放：`/market points give|take`

- **仅服主**（服务器控制台照常可用）。`take` 是回收，余额不会被扣成负数
- 命令树里有一个 `@s` 字面量分支：`/market points give @s N`（`@s` = 执行命令的玩家自己）

⭐ **RP 当任务奖励自动发（可选）**：在 RP 配置界面打开「give/take 权限下放」（`rpAsQuestCurrency`，默认关）后，**玩家身份的 OP（命令等级 ≥ 2）**也能用这两条命令。

- 用途：FTB Quests 之类的任务模组要把 RP 当奖励发。它们在 1.20+ 只有一种执行形态 —— **以完成任务的玩家身份执行、并临时把权限提到 N 级**（FTB 的「运行等级」），既不是服主也不是控制台；不开这个开关就永远被拒
- 给服主的两步操作：① 打开这个开关 ② 任务奖励写 `/market points give @s N` 且**运行等级设 ≥ 2**
- ⚠ 打开 = 接受「任何玩家 OP 都能发 RP」（`/op` 可以被传递给任何人）；只把 RP 当充值货币、由你手动发放时请保持关闭
- ⚠ 这个开关**只管发放 / 回收这两条命令**，权限授予、撤销坏账等仍然只认服主

### 2.2 兑换码（本地码）

一串文本码，玩家在 RP 商城的兑换框里粘贴、点「兑换」（或 `/market points redeem <码>`）立刻到账，并留下兑换记录。

- 生成 / 查看 / 作废 / 清理在**管理面板底部的「兑换码」界面**（判「兑换码」权限节点），不必记命令参数
- 生成时可以设面额、张数、每张可用次数、有效期，也可以绑定某位玩家
- 列表**只显示码的前缀**（码 = 钱，整屏明文截个图就等于送出去一批）；每行的复制按钮才把完整码放进剪贴板
- 一次性生成 ≤10 张会在弹窗里列出，更多则写入 `config/cobblemarket/points/` 下的文件并给出路径

### 2.3 兑换码（外部签名码）

有自己的充值网站 / 发卡网的服主，可以在服务器之外签发兑换码：玩家在网站付款后自动拿到码，再进游戏兑换。

- 网站与 MC 服务器**零耦合**：不开端口、不做内网穿透、网站挂了也不影响游戏
- 服务器只做一件事 —— 验签；任何能算 HMAC 的平台都能签（PHP / Node / Python / Java）
- 外部码**不能**限次 / 绑定 / 作废（服务器不存它们，只记已用 serial）；需要这些能力请用本地码
- 协议、配置与测试向量见 [RP 外部签名码](/points-external)

### 2.4 游戏内充值（个人收款码）

玩家在游戏内选档下单 → 扫码付款 → 点「我已支付」→ 服主核对收款账单后一键发放。

- 适合国内个人服主：个人微信 / 支付宝收款码即可，不需要商户资质
- 模组**不碰钱、不做支付通道**：「我已支付」是玩家的**声明，不是证据**；确认发放前请看自己的收款账单
- 订单带 6 位订单号，按订单号核对；详见 [RP 充值](/points-recharge)

### 2.5 数据包奖励（可选）

用数据包配「捕捉某只精灵给多少 RP」「整包模组的精灵给多少」「传说 / 闪光 / 头目给多少」这类规则，玩家做这些事时自动到账，动作栏弹「奖励 +N」并响一声到账音。

- 支持捕捉、孵化、战斗胜利、化石复活、进化五种行为；条件可自由组合，支持排除、重复递减、每日上限
- ⚠ 默认关着 —— 打开等于允许游戏行为自动发钱，务必先确认 RP 的来源定位
- 规则怎么写、怎么排错见 [RP 奖励规则](/points-rewards)

## 三、玩家怎么花 RP

- **上架二选一标价**：精灵与物品的上架界面在价格框旁有货币按钮（主货币 ↔ RP 图标），选哪种币就收哪种；上架费也按该币种收
- **市场按货币分开看**：精灵市场、物品市场、拍卖场、求购单都有货币按钮 —— 两种币的价格不可比，混排会让排序与筛选失去意义，所以**一次只显示一种**；切换后回到第一页。币种会跟着界面走：在 RP 页点「上架」，上架界面默认就是 RP；上架完返回也停回 RP 页
- **RP 收入直接到余额**：RP 卖出去的钱不进「待收款」账本，没有「收款」按钮；购买 RP 商品时也不出现喵喵支付（RP 与主货币不等值，不可分期）
- **交易历史里能看出商城成交**：RP 商城的成交在卖家栏显示为「▣ 商城」（金色），而不是上架的管理员名；交易账本 CSV 末尾的「来源」列同样区分 market / shop，「币种」列区分 PRIMARY / POINTS

## 四、RP 余额在哪看

- **余额 HUD**：主余额框的**下一行**显示 RP（含余额变动时的 +绿 / −红浮动提示）。它与主货币**共用一个背景框、也共用同一个显示开关**（两行一起显隐、一起淡出）；服务器关闭 RP 时这一行自动隐藏
- **市场入口界面**：余额下方固定显示一行 RP（服务器关闭 RP 时不出现）
- **市场 ID 卡 / 全服玩家总览**：都有 RP 余额行；玩家总览支持**按 RP 余额排序**（排序按钮上用货币图标表示，界面里不出现「RP」字样）。⚠ 服务器关闭 RP 时这一项不出现
- **命令**：`/market points check` 查自己（人人可用）；查别人需要「查余额」权限节点

> ⚠ 把本模组的余额 HUD 关了，RP 也会一起隐藏 —— 这时请用市场入口界面那行 RP、ID 卡或 `/market points check` 查看。如果是为了避免和别的模组的余额 HUD 重叠，更推荐关掉对方的 HUD、保留本模组这一个（它同时显示两种余额）。

## 五、RP 商城（服主经营）

RP 商城界面中间的商品区由**持有「RP 商城」权限节点**的人单方面经营 —— **8 列 × 4 行共 32 格**，点任意格子即可上架精灵或物品，玩家用 RP 购买。

⚠ 商城本身由 `pointsMainShopEnabled` 单独控制（默认关）—— 关闭时市场入口里的商城按钮置灰、点击提示未开放；这只影响主商城，**自定义 NPC 商店照常营业**。

- **卖的是配方而不是实物**：卖出去的那只是照规格当场生成的，**初训家默认就是买家**（上架时可以改成配信名）；服主的名字不会印上去
- **精灵商品能配得很细**：物种、形态、变体、闪光（不闪 / 必闪 / 按概率出）、等级、性别、性格、特性、球种、体型、头目、太晶属性、超极巨化、极巨等级、携带物、能否再交易、**保底 V 数**，以及**四个技能槽**（该物种 / 该形态能学的技能全部可选，列表顶上还能按来源分档筛选；教学招与形态专属招也在候选里）
- **初训家（配信）**：「保底 V 数」右边的输入框填上名字（如「サトシ」），从这一格买到的每一只都会把初训家写成那个名字；留空 = 买家本人。购买窗会显示买到手的初训家是谁（服主没填时那一格不显示），名字上限 16 个字符
- **物品商品完整复制手上那件**：上架物品界面搜索框左边的小手按钮，取的是手上物品的**全部组件**（附魔、磨损、自定义名、模组自定义的插件 / 升级数据），买家拿到的与服主手上那件一模一样。⚠ 想卖全新的，改用搜索框选物品
- **库存按格设置**：留空 = 不限量（默认），填数字 = 限卖几份
- **价格不受规则约束**：商城价格由服主自己定，不受价格限制表、黑名单或手续费影响
- **变体是独立一栏**：形态只管地区形态与 Mega，物种特性（花纹 / 帽子 / 奶油装饰 / 斑点等）走「变体」，每个维度各选一个，列表只列该物种模型上真有的那些
- **闪光播报**：玩家从商城买到闪光精灵时，全服聊天播报 `[Ⓡ 商城] 恭喜 玩家 购买到了 ★[精灵名]！`（游戏内不出现「RP」字样）；精灵名可悬停看大图与完整信息。定期领取店领到闪光时同样播报，措辞是「领取到了」，前缀取进店那个 NPC 的名字

⚠ 想在 NPC 处开店（玩家右键打开），见[自定义 NPC 商店](/custom-shops)

### 5.1 战斗形态、「非法」标记与解锁开关

商城是**直接造出**一只已经处于某形态的精灵，而「在正常游戏里需要先满足条件才变得了身」的那类形态（Mega / 原始回归 / 达摩模式等）的前置条件**从来没被满足过** —— 形态与道具的配套关系是破的（Mega 精灵却没带 Mega 石），还白省下一个携带物位。

- 上架界面的「添加」按钮左侧有一枚**常驻**的警告符号（⚠），点开是一屏说明。⚠ 认这类形态靠固定清单，你自己加的数据包 / 附属模组带来的新形态不在清单里 —— 所以入口常驻，判断交给服主
- 允许这类精灵出现是**有意保留**的：服主可能就是故意卖收藏品 / 活动奖品，模组只做告知与标注，**服务端不拦**

精灵上架界面还有两枚与性质有关的开关：

- **「非法」开关**（「添加」按钮左侧，常驻，只有精灵上架界面有）：选中后，从这一格买到的每一只都会带上 `cobblemarket:illegal` 标记，**打在精灵自己身上、跟着精灵走** —— 买家转手卖出也还在。商城格子左上角会标红、购买窗也看得到
  - 它标的是**这只正不正常**、**不是从哪来**；与自动打的 `cobblemarket:shop`（来源 = 商城）是两回事，合法的商城精灵不会被误伤
  - 两个标记都写进存档、玩家洗不掉；做数据包 / 整合包的服主也可以自己写 `"cobblemarket:illegal"` 来标记自制的非法精灵
  - 撤销只有一条路：`/market tag remove <玩家名> <槽位> <标签>`（**仅服主**，够不到 PC —— 要撤 PC 里那只，让玩家先换到队伍里）。`shop` 来源标记有意不可撤
- **解锁开关**（右上角「快照」左边，默认是把锁）：选中后，特性与技能候选不再限于该物种 / 形态，可以从 Cobblemon 的全部特性与全部技能里挑。⚠ 选中它**会自动标为「非法」**；取消「非法」时它也一起关掉，并把越界的特性 / 技能清回「随机」

### 5.2 商城权限

「RP 商城」权限节点管上架 / 编辑 / 下架商品 —— 它决定玩家花 RP 能换到什么，属于发东西的把关权，授予前请确认。

⚠ **RP 这块不认 OP**：商城上下架、兑换码生成、RP 配置读写一律按权限节点或服主判定；发放 / 回收 RP 的两条命令只限服主（下放开关见 §2.1）。

## 六、审计与对账

RP 的每一次变动都写 CSV 到 `config/cobblemarket/points/`：

- 发放 / 回收 / 兑换 / 充值发放，以及**玩家之间用 RP 成交的市场、拍卖、求购**（买卖双方各记一笔，手续费写在详情里；拍卖与求购的钱在下单时就已扣走，所以这两类按成交落账）
- 充值订单另有一份**订单流水**：创建 / 玩家声明已付 / 发放 / 作废，每一步都查得到
- 与交易账本的分工：交易账本回答「货去哪了」，RP 账本回答「RP 怎么流动的」

## 七、把余额排行显示在服务器里

模组每隔几分钟把**全服余额**写进存档目录的 `cobblemarket_points/`：

```
<存档>/cobblemarket_points/
├── ranking.json          全服排行
└── players/<uuid>.json   单人余额
```

- **只在余额真的变了的时候才写盘**，间隔默认 5 分钟（`pointsRankingExportMinutes`，1~1440）
- 字段包含 `name` / `uuid` / `points`；`uuid` 是有意多给的 —— 玩家改名后榜不会错位
- 模组**只提供文件和命令、不做显示**：全息板 / 告示牌 / 网站由服主自己搭，怎么展示由你决定
- 想自己控刷新节奏（命令方块 + 时钟）：用 `/market points update` 立刻刷新一次（权限等级 ≥ 2，命令方块可用）

服主还可以用 `/market points top [页码]` 在游戏内查看全服余额排行：全量、10 人一页、可点翻页。⚠ **仅服主可见** —— 全服余额是敏感信息；要让全服玩家看到，用上面的导出文件自己搭。

## 八、存档文件

RP 相关的存档文件都在 `<世界存档>/data/` 下：

| 文件 | 内容 |
|---|---|
| `cobblemarket_points.dat` | RP 余额 |
| `cobblemarket_points_rewards.dat` | 奖励进度 + 当天每日上限（重置它**不动余额**） |
| `cobblemarket_point_codes.dat` | 本地兑换码 + 外部码的已用 serial |
| `cobblemarket_point_orders.dat` | 充值订单 |
| `cobblemarket_point_shop.dat` | RP 商城的商品与库存 |

余额排行的导出文件在 `<世界存档>/cobblemarket_points/`，不在 `data/` 里；换图 / 备份说明见 [存档数据位置](/save-data)。

## 九、换掉 RP 的图标

RP 的图标走资源包覆盖，不提供游戏内设置：

| 用途 | 文件 |
|---|---|
| 行内符号（金额旁的小图标） | `assets/cobblemarket/textures/gui/currency/points_symbol.png` |
| 充值界面的大图 | `assets/cobblemarket/textures/gui/currency/points_icon.png` |

做一张同名同尺寸的图放进服务器资源包即可，全服玩家统一生效。

## 十、常见问题

### RP 能换成主货币吗？

不能。RP 与主货币是两套账本，没有兑换入口，也不能转移给其他玩家（玩家间 RP 交易只是「用 RP 买卖东西」，不是转账）。

### 关掉 RP 总开关后，玩家已经有的 RP 会消失吗？

不会。余额还在存档里，只是界面上不再显示、也不能用于交易；重新打开即恢复。

### 外部码和本地码该用哪个？

想在游戏内管理、要限次 / 绑定 / 作废，用本地码；有自己的网站并希望玩家付款后自动拿到码，用外部签名码。两者共用一个兑换入口。

### RP 商城和玩家之间的 RP 交易是一回事吗？

不是。RP 商城是服主单方面经营（卖配方、价格不受市价规则约束）；玩家间 RP 交易是玩家拿 RP 互相买卖，受 `pointsMarketEnabled` 开关控制。
